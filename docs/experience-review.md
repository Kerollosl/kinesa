# Kinesa experience review — 0.10

The companions now use original procedural Three.js models. Leo has a sculpted mane and projecting muzzle; Lou has curved ivory horns and cloven hooves; Juno has a white head, hooked gold beak and layered brown wings; Mattie has swept curls, a lavender tunic and a gold halo. The reference-led cuteness pass gives the cast larger heads, shorter stockier bodies, fuller cheeks and broader wings. Leo’s mane is warm copper with swept locks; Lou’s muzzle and horns are softer; Juno has a smiling open hooked bill and graceful feather fans; Mattie has fuller curls, welcoming hands and a shorter tunic. Curved warm irises and larger pupils retain a visible cream rim, replacing the small staring pupils and detached eye details. These are solid meshes with real X/Y/Z depth, including the faces, feathers, paws and hands. Turning a character reveals its geometry. No external generation service or third-party mascot assets were used for this rebuild.

Motion blends native joint deltas over each model’s captured rest pose. Heads, torsos, shoulders, elbows, wrists, wings, ears, tails and Mattie’s halo have independent motion. Physical eyelids close over the eyes; eye attention leads the heavier head and torso follow. Per-character breathing and curiosity continue through greetings. Repeated taps retarget damped springs without resetting their current position or velocity, and completed gestures release into the ongoing idle.

One shared WebGL studio renders the cast and face-focused portraits into transferred transparent avatar canvases in a background worker. Geometry, shader compilation, spring updates and rendering stay off the page thread so navigation and input can respond independently. Browsers without transferable canvases use the same studio on the main thread. This preserves normal page clipping, stacking and glass surfaces while avoiding a separate GPU context for each character. Static surfaces merge within articulated groups, and removed rigs dispose their geometry and materials. Directional studio lighting and soft contact shadows show form and ground the feet.

The shared animation scheduler suspends offscreen characters, hidden tabs and the inert page beneath dialogs. Scene pause freezes the exact pose; resume resets the wall-clock baseline so there is no catch-up jump. Reduced motion uses a static semantic pose while deliberate interactions remain available. Transparent, self-hosted renders of the same models cover startup, unavailable WebGL and context loss. Worker notifications are published after the render callback returns, and the page reveals the canvas on its next rendering frame without reading GPU pixels back onto the page thread. Preview exports additionally verify nonempty pixels before saving. These posters are fallbacks, not animation frames.

Validation: **16 unit tests and 25 browser tests passed**, plus the production build. The worker animation checks inspect rendered canvas pixels, genuine geometry depth and physical joint quaternions, including repeated greetings, pointer yaw, exact pause/resume, dynamic reduced motion, one shared worker/context and a usable poster fallback. The complete game-flow suite also passed after moving graphics off the page thread, including interrupted spins, four-player matches, unique assignment, bots, room editing, storage failures and mobile layouts. Chromium software-rendered checks confirm that navigation and game setup remain responsive while the avatars animate; this is not a frame-rate guarantee for physical devices. Production cold-load checks also passed with actual rendered pixels and navigation in both the worker and main-thread compatibility paths. Real-device GPU and Safari testing remain follow-up work.

Motion coverage checks 30/60/120Hz trajectories, interruption continuity, eye/head/body attention timing, native XYZ wing movement, grounded feet, asynchronous blinks, bounded delayed frames, reduced-motion poses and return to idle. Browser motion checks inspect actual geometry depth, rendered pixels, physical joint quaternions, persistent instances, repeated greetings, pointer yaw, exact pause/resume, dynamic reduced motion and a single shared WebGL context.

The frontend flow review includes 320px and 390px phone layouts, blocked local storage, complete four-player turns, interrupted and resumed play, empty and earned collection states, incorrect feedback, completed results and dialogs. Existing automated accessibility checks supplement the visual and interaction review; this pass does not establish performance or accessibility results on physical devices.

The app remains a local frontend preview. Matchmaking uses practice bots, friends use one device, and the question deck contains 12 samples. No production question database or remote multiplayer service was added. The publication target is the private `Kerollosl/kinesa` repository.
