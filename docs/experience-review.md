# Kinesa experience review — 0.11

The companions restore the original illustrated designs: Leo’s fluffy orange mane and warm smile, Lou’s stocky calf silhouette and ivory horns, Juno’s expressive white head and layered brown feathers, and Mattie’s curls, lavender tunic and halo. Their familiar faces and soft dimensional shading remain in the painted artwork. The cast uses articulated illustrations, not procedural 3D meshes.

Painted heads, bodies, wings and arms stay on persistent joints. Continuous breathing and curiosity blend with pointer attention and greetings through damped springs; repeated taps retain each spring’s position and velocity. Blinks use painted eyelids matched to the original faces. Independent wing and halo movement adds life while keeping the original silhouettes recognizable.

A shared animation scheduler updates visible companions without React rerenders on every frame. Scene pause preserves the exact pose, and resume resets the wall-clock baseline to avoid a catch-up jump. Hidden tabs, offscreen characters and backgrounds behind dialogs suspend. Reduced motion uses static poses while the game’s deliberate interactions remain available. Full-body scenes and face-focused portraits share the same self-hosted artwork.

Validation: **13 unit tests, all 26 browser checks and the production build passed**. Motion checks cover spring continuity, bounded delayed frames, reduced-motion poses and return to idle. Browser checks exercise persistent parts, repeated greetings, pointer attention, exact pause/resume, dialog suspension and dynamic motion preferences. They also verify that the original artwork and high-fives work with workers and WebGL disabled. The restored cast gallery is pixel-identical to the earlier illustrated lineup.

The frontend flow review includes 320px and 390px phone layouts, blocked local storage, complete four-player turns, interrupted and resumed play, empty and earned collection states, incorrect feedback, completed results and dialogs. Existing automated accessibility checks supplement the visual and interaction review; this pass does not establish performance or accessibility results on physical devices.

The app remains a local frontend preview. Matchmaking uses practice bots, friends use one device, and the question deck contains 12 samples. No production question database or remote multiplayer service was added. The publication target is the private `Kerollosl/kinesa` repository.

See the [updated screenshots and animation](../README.md#credits). Regenerate the complete preview set with `node scripts/capture-preview.mjs` while the Vite development server is running, or use `--companions-only` for the illustrated cast gallery.
